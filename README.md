# Agent Editor

محیط خصوصی و محلی برای طراحی، ساخت، آزمایش، مدیریت و ارتقای Agentهای هوش مصنوعی.

> **وضعیت:** اسکلت فاز ۱ در مخزن ایجاد شده است. اجرای واقعی و تست روی دستگاه هدف هنوز باید انجام شود.

## هدف پروژه

Agent Editor یک ابزار مهندسی اختصاصی و تک‌کاربره است؛ نه SaaS، نه بازار Agent و نه پلتفرم عمومی. هدف، ایجاد محیطی یکپارچه برای تعریف Agent، اتصال مدل، مدیریت ابزار و مهارت، اجرای کنترل‌شده وظایف و ارزیابی نتایج است.

## اصول طراحی

- **Local-first:** اطلاعات محلی و خصوصی به‌صورت پیش‌فرض روی دستگاه کاربر نگهداری می‌شوند.
- **Provider-agnostic:** اتصال مدل‌ها از طریق Model Gateway انجام می‌شود.
- **Modular:** هسته، مدل‌ها، ابزارها، مهارت‌ها، حافظه و رابط کاربری مرزهای روشن دارند.
- **Approval-first:** عملیات حساس یا دارای اثر بیرونی قبل از اجرا به تأیید صریح نیاز دارند.
- **Observable:** اجراها باید شناسه، وضعیت، رویداد و خطای قابل بررسی داشته باشند.
- **Mobile-conscious:** رابط وب باید در مرورگر موبایل قابل استفاده باشد.

## ساختار فعلی

- `backend/`: سرویس FastAPI، تنظیمات و تست پایه
- `frontend/`: رابط React + TypeScript + Vite
- `.github/workflows/`: بررسی خودکار Backend و Frontend
- `docs/`: معماری و دستورالعمل‌های اجرا

## شروع سریع

ابتدا راهنمای [اجرای فاز ۱](docs/PHASE_1_RUNBOOK.md) را دنبال کن. Backend به‌صورت پیش‌فرض روی `127.0.0.1:8000` و Frontend روی `127.0.0.1:5173` اجرا می‌شود.

- سلامت API: http://127.0.0.1:8000/api/v1/health
- مستندات API: http://127.0.0.1:8000/api/docs

## امنیت و حریم خصوصی

کلیدهای API، فایل‌های حافظه، پایگاه داده، فایل‌های workspace و خروجی اجرا نباید وارد Git شوند. سرور فقط روی loopback اجرا می‌شود. اجرای فرمان سیستم و عملیات حساس در فازهای بعد نیز باید تحت مجوز محدود و تأیید کاربر باشد.

## وضعیت توسعه

فاز ۱ شامل ساخت اسکلت Backend، Frontend، endpoint سلامت، تست پایه و CI است. تا زمان اجرای تست‌ها در محیط هدف، این اسکلت «ایجادشده» محسوب می‌شود و نه «تأییدشده در اجرا».
